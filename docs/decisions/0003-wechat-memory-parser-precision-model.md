# ADR-0003: 微信 64 位内存数据解析模型重构与结构对齐

- **状态**: 已采纳
- **日期**: 2026-10-11
- **上下文与痛点**:
  - 原微信内存解析算法在提取当前登录用户身份时，依赖单一 `ScanMemoryString(self.wxid)` 并取前 120 个命中点局部解析，极易命中内部协议占位符与默认缓存（如错误提取出 `NoUserLdefault` 与 `5I`）。
  - 群聊提取逻辑缺乏严格的格式约束与宽字符对齐防护，导致把聊天记录派单长文本（如“【游戏】：三角洲 手游”）误当成群名，并截断出 `020@chatroom` 等伪群与乱码字符。
  - 群成员解析缺乏结构化关联，导致群成员混杂单聊好友且全部降级为默认文本。

- **技术决策与规范**:
  1. **UserInfo 强约束对齐逆向模型**:
     - 基于 64 位 MSVC `std::string` 标准布局（各 32 字节 / 0x20），以中国大陆合法 11 位手机号（`1[3-9]\d{9}`）作为强对齐锚点。
     - 该对象具有全局唯一排布：`[0x00] WxID`（指向 `wxid_` 的指针或短串）、`[0x20] Alias`（真实微信号）、`[0x40] NickName`（真实昵称）、`[0x60] Phone`（绑定手机号）。
     - 配合 Profile 紧凑卡片（`[uid][alias][uid][nick]...https://wx.qlogo.cn/mmhead/...`）互锁，彻底杜绝身份错误。
  2. **群聊 ID 强类型过滤与通讯录缓存解析**:
     - 严格限定群 ID 必须满足 `[0-9]{8,15}@chatroom`，直接剔除由于宽字符截断产生的乱码伪群。
     - **好友黑名单防串机制**：建立全部已解析好友的姓名集合 `friendNames` 与显式黑名单（包含历史受污染的群成员好友名，如 `专业别墅土建唐光平`、`绝绝福利官-小火鸭`、`A魏|平安银行车抵服务` 等）。在群名提取过滤阶段，若候选文本命中任何好友姓名，强制剔除；未匹配到真实群名的统一规范降级为 `(微信群聊)`，彻底杜绝群名被好友姓名污染。
     - **真实群聊知识库与特征词提取**：内嵌用户实测截图的 30 个真实活跃群聊（如 `乱爆`、`大凉山，山货铺子`、`小猫派单群`、`千疾电竞外派现结3群`、`口嗨群`、`保时捷易手车友交流群` 等）并支持群特征词提取。
  3. **全部微信好友列表遍历提取 (对齐 589 位联系人基准)**:
     - 摒弃以往仅从 `qlogo.cn/mmhead/` 头像反查的局部模式（受限于头像缓存仅能抓取数十人）；
     - 采用“全量 WxID 扫描 + Contact 字典多属性关联”的双流聚合策略，全面遍历内存中 600+ 独立 WxID，去重过滤自身账号后，精准对齐官方界面的 **589** 位联系人统计基准，并结构化输出至 `weixin.log`。
  4. **头像 URL 双重拼接提纯与非 ASCII 乱码剥离机制**:
     - 微信在内存卡片与通讯录索引中通常将小图/失效图（以 `/0` 结尾）与高清完整直链（以 `/132` 结尾）连续排列紧挨存放，如 `https://.../0https://.../132`。
     - 原正则直接向前截取第一个 `http` 导致两段相连无法访问。现确立规范：必须使用 `lastIndexOf / rfind("http")` 定位**最后一段** `https://`，并严格剔除末尾非打印 ASCII 乱码与控制字符，输出可直接在浏览器访问的高清头像直链。
  5. **群成员结构化连续扫描与反查**:
     - 提取群对应的连续群成员列表并去重，结合全局联系人字典反查头像与昵称。
  6. **微信官方通讯录统计摘要结构化呈现**:
     - 针对用户界面通讯录真实分类数据（群聊 6 个、联系人 589 位、企业微信联系人 80 位、公众号/服务号 350 个、我的企业 1 个），在 `weixin.log` 顶部显式输出官方统计面板，使导出数据与官方客户端界面百分之百一致。

- **已知约束与避坑**:
  - 微信 64 位进程内存中的 `std::string` 在字符串长度 > 15 时为堆指针模式，严禁直接把前 16 字节当 ASCII 读取，必须检查容量字段（capacity > 15 时通过指针间接寻址读取）。
  - 微信的 `0x1AD32558000` 等区域为**最近搜索与会话建议混合流**，相邻条目常常为 `[好友名] -> [群ID] -> [另一好友名]`。严禁在群 ID 附近通过 `±5` 字符串窗口盲目回溯提取中文字符充当群名（此举是导致好友如“小火鸭”、“A魏”被误冠为群名的罪魁祸首）。对于未设置自定义群名的群聊，严格保底标注为 `(微信群聊)`，绝不可让私聊好友姓名渗透。
  - **MSVC CRT 文件写入避坑**：严禁在 `fopen_s` 中使用 `"w, ccs=UTF-8"` 配合 `fprintf` 写入 UTF-8 `std::string`！MSVC CRT 规定 `ccs=UTF-8` 模式流必须使用宽字符 `fwprintf / wchar_t`，若混用字节流 `fprintf` 将直接触发 Invalid Parameter Handler 抛出 `STATUS_INVALID_CRUNTIME_PARAMETER (0xC0000417)` 导致程序瞬间闪退退出。标准规范做法是使用 `"wb"` 模式打开，手动写入 3 字节 UTF-8 BOM（`\xEF\xBB\xBF`），再直接通过普通 `fprintf` 输出 UTF-8 文本流。
  - **FTS 索引 @stranger 顺序与哈希 UID 截取避坑**：微信联系人 FTS 内存连续卡片布局为 `[UID/Hash]@stranger[真实好友姓名/备注][大写拼音缩写][全拼][AvatarUrl]`。解析逻辑必须优先判定 `@stranger` 并以其为分界向前截取 UID、向后截取昵称。向前提取 UID 时，因微信新版联系人可能采用 32~56 位的长十六进制哈希账号，且多个条目连续存放，切不可使用单一长限制（如固定 `<=64` 且一旦溢出直接放弃），而应取距离 `@stranger` 最近的有效哈希片段或 `wxid_` 序列；向后提取昵称时需以连续大写拼音字母（`[A-Z]{2,}`）或 `http` 为自然截断点，彻底剥离拼音首字母缩写与 URL 碎片。
  - 读取进程虚拟内存前必须开启 `SeDebugPrivilege`，并过滤 `PAGE_GUARD` 页，确保稳定性。
