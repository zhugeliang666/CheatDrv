# ADR-0182：X2 共享区无锁环形日志队列
- **状态**：已采纳（运行时复测待完成）
- **日期**：2026-11-03
- **上下文**：`VT_SHELLCODE_DEEP_UNWIND=1` 时，X2 内部直接调用 `DbgPrintW` 或再次进入 `SpoofCall` 会扩大故障面；单槽共享记录又会覆盖旧事件，无法承载持续触发。
- **决策**：R3 `CustomHookDispatch2` 使用 512 槽 MPMC 预留算法，将诊断记录写入数据区第三页起的环形队列；每个槽以 `Sequence` 发布和回收，记录包含模式、运行标志、槽地址、CPU 上下文地址、调用点、原始 RSP、四个寄存器参数以及最多 5 个原始栈槽值。R3 不调用 `DbgPrintW`、`VirtualQuery` 或 `SpoofCall`。
- **驱动行为**：维护工作项在已取得 RuntimeSlot 租约且 `state == 2` 时从上次消费位置开始顺序读取并排空全部已提交槽，回写槽位释放序列后由驱动输出 `[VDBG] X2 shared log` 和返回槽明细；共享区同时保存 `DroppedCount`，溢出时明确报警。目标数据区按队列大小扩展，释放和失败清理沿用原有统一路径。
- **限制**：这是有限容量、非阻塞队列；无限速率生产无法由有限共享内存保证绝对不丢。队列满时不阻塞 X2，而是递增 `DroppedCount`，禁止静默丢失。
- **验收**：DebugShellcode 与 Machenike 构建成功；回滚脚本恢复原文件并删除新增共享头文件；重新加载驱动和目标进程后，应观察到驱动顺序输出每个已提交事件，且 R3 不再直接打印。
