# ADR-0177: Deep 私有栈复制补齐入口原始返回地址槽
- **状态**: 已采纳
- **日期**: 2026-11-01
- **上下文与痛点**: 首次 Hook 使用原生栈能够正常返回；初始化完成后再次触发或卸载后重新 Hook 进入 Deep 私有栈路径时，X1/X2 复制循环只复制 `0x30` 个 QWORD（`0x180` 字节），遗漏保存区紧邻的入口原始返回地址。私有栈顶返回槽保持为零，最终 `ret` 跳转到 `RIP=0`，触发 `0xC0000005` 执行访问违规。
- **技术决策与规范**: X1 的 `X1CopySavedFrame`、X2 的 `X2CopyToPrivate` 与 `X2CopyFromPrivate` 统一使用 `0x31` 个 QWORD；其中前 `0x30` 个 QWORD 是 `HOOK_CPU_CONTEXT`，第 `0x31` 个 QWORD 是入口原始返回地址。现有 `TopShadow` 至少提供 `0x20` 字节余量，额外复制的 8 字节不会触及 Arena。嵌入镜像必须由修改后的 DebugShellcode 重新生成。
- **已知约束与避坑**: `0x30` 不能作为完整 Deep 入口帧长度，只适用于纯 `HOOK_CPU_CONTEXT` 数据；禁止恢复为 `0x60`，否则会越过私有栈顶并覆盖静态 Arena。修改后必须执行同输入的基线/修改版检查、重新构建 DebugShellcode 与驱动、校验嵌入镜像哈希，并验证回滚后源文件哈希恢复。
