# ADR-0139: hv::Call 用户态/内核态调用 API 重命名与项目集成

- **状态**: 已采纳
- **日期**: 2026-10-30
- **上下文与痛点**: 原有 `hv::Call` 与 `hv::CallK` 都使用过短名称，调用点无法直接表达 Guest 执行权限；项目内还存在大量旧名称引用，容易把用户态返回桩与内核态返回桩混用。
- **技术决策与规范**: 将用户态伪造堆栈调用入口统一命名为 `hv::CallUser`，将内核态伪造堆栈调用入口统一命名为 `hv::CallKernel`；同步更新 `game.h` 定义、业务调用点、VM-exit/VCpu/Hypercall 诊断注释及桥接注释；两者继续共享同一套 Guest 栈快照、参数布置、返回陷阱和上下文恢复实现。
- **已知约束与避坑**: `CallUser` 使用用户地址空间返回桩，`CallKernel` 使用 `g_ghv->kernel_blank_va` 内核返回桩；禁止恢复旧 `Call`/`CallK` 兼容别名，避免调用点重新失去 Ring 级别语义；`Call2/Call3/Call4` 属于历史接口，不纳入本次重命名。
