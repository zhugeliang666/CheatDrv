# ADR-0057: 硬件断点动态 64 位原子指纹感知、DR7 使能前置门禁与惰性调度脏数据误报根除
- **状态**: 已采纳
- **日期**: 2026-10-23
- **上下文与痛点**:
  - 在三角洲行动等受反作弊（ACE / TP）保护的环境下，反作弊自身在用户态线程中设置了硬件断点以监控其关键自检例程；
  - Windows 线程调度器（`KiSwapThread`）出于极速切换性能考虑，在切出非调试线程时仅将 `DR7` 复位为默认值 `0x400`（所有断点停用），而**不会耗费 CPU 指令擦除物理寄存器 `DR0~DR3`**；
  - 驱动原 `AuditHardwareBreakpoints` 仅简单判断 `(dr7 & 0xFF) != 0 || dr0 != 0 ...`，导致读到 CPU 物理核心上的残留脏数据并误触发 `STATUS_BREAKPOINT` 异常报警；
  - 此外，此前为防止刷屏引入的单次锁定（Sticky Latch）在初次上报后彻底关闭感知，导致逆向分析人员或反作弊后续切换、新增断点时驱动无法再次感知与取证。

- **技术决策与规范**:
  1. **DR7 使能位绝对前置门禁**:
     - 严格遵循 x86/x64 硬件架构规范，以 `(dr7 & 0xFF) != 0` 作为断点激活生效的绝对前置条件；若低 8 位全为 0（如 `DR7=0x400`），直接认定为断点停用状态并放行。
  2. **64 位动态原子断点指纹（Atomic HWBP Fingerprint）**:
     - 弃用静态单一布尔锁，改用 `s_LastHwbpFingerprint` 记录当前活跃的断点组合状态；
     - 采集 `DR0, DR1, DR2, DR3, DR7` 共 5 个 64 位整数，经 FNV-1a 极简异或置换生成 64 位指纹；
     - 通过 `InterlockedCompareExchange64` 实现零锁并发认领：
       - **断点持续未变**: 指纹相同，静默跳过，彻底消除周期性巡检刷屏；
       - **断点变更/新增/首启**: 指纹发生变动，即时捕获最新现场并触发上报；
       - **断点解除（(dr7 & 0xFF) == 0）**: 原子清零指纹缓存，确保下次再次激活下断时能重新感知。

- **已知约束与避坑**:
  - 指纹运算与原子比较必须在无锁纯计算中完成，严禁在 `AuditHardwareBreakpoints` 中分配内存或使用自旋锁，保证在 `PASSIVE_LEVEL` 至 `DISPATCH_LEVEL` 下安全稳定执行；
  - 严禁在 `(dr7 & 0xFF) == 0` 时读取并上报 `DR0~DR3`，彻底杜绝操作系统惰性上下文切换带来的硬件残留误报。
